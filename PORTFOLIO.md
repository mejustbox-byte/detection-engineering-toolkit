# Демонстрация для портфолио

Цель: показать полный инженерный цикл и качество доказательств, не заявлять гарантированную оценку CVP/Defense Access. Критерии конкретной программы проверяются отдельно; проект демонстрирует detection engineering независимо от названия программы.

## Демонстрация текущего этапа

1. Показать требования и ограничения выбранного ATT&CK поведения.
2. Выполнить list и bundle; объяснить logsource, UUID, false positives.
3. Открыть оба SIEM запроса и показать разные модели данных.
4. Выполнить validate на positive/negative fixtures, затем deliberately wrong expected → exit code 1.
5. Показать Atomic parser с собственным synthetic test как проверку интерфейса, затем выбранный настоящий YAML после ручного review.
6. Явно показать not_run real SIEM/Atomic и план следующего лабораторного доказательства.

## Финальная демонстрация после стенда

Добавить pinned Atomic procedure → endpoint raw event → ingestion → фактический SIEM result → негативный тест → cleanup/rollback. Публиковать только очищенные данные, собственные правила и synthetic аналоги. Приложить commit, lock, query/rule hashes, OS/SIEM versions и независимый review.

Технический тезис портфолио: «связал наблюдаемую процедуру, модель телеметрии, portable rule, backend pipeline и проверяемое свидетельство». Не утверждать, что один сигнал покрывает всю технику или что конвертация эквивалентна обнаружению.
