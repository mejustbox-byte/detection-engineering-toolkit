# Лаборатория событий создания процессов Windows

Статус: подготовка alpha. Проверены офлайн-импорт и оценка на Linux. Сбор Windows, доставка в SIEM, исполнение правил и Atomic пока не проверены. Разбор синтаксиса PowerShell в Windows CI не является проверкой сбора.

## Область и подготовка

Используйте одноразовую Windows VM с локальной тестовой учётной записью, без производственных секретов и со снимком. Изолируйте VM от производственных сетей. До изменений сохраните приватно сборку Windows, версию PowerShell, версию SIEM и исходные настройки аудита.

Вручную включите успешный аудит создания процессов в расширенной политике аудита / подробном отслеживании и включение командной строки в события создания процессов в административных шаблонах / системе / аудите создания процессов. Названия зависят от языка ОС и управления политиками. Проверьте действующие настройки выбранной VM: доменная политика может переопределять локальную. Сборщик политики не настраивает.

Аудит командной строки записывает аргументы всех отслеживаемых процессов открытым текстом: в Security могут попасть пароли и другие секреты. Используйте только лабораторные данные. После проверки восстановите снимок или сохранённые исходные значения политик. Производственные журналы не очищайте.

## Сбор на Windows

Из корня репозитория запустите Windows PowerShell 5.1 с правом чтения Security. Каталог результата не должен существовать. Toolkit не требует изменения execution policy; соблюдайте правила выполнения скриптов вашего стенда.

```powershell
.\lab\windows-4688\Collect-LabEvents.ps1 -OutputDirectory .\lab-output\run-001 -LabAcknowledgement
```

Сборщик запускает whoami, hostname, ipconfig /all и отрицательный контроль cmd /c ver. Читает события Security 4688 по соответствующим PID/образам за ограниченный интервал. Не меняет политики аудита и не подключается к SIEM. Пишет UTF-8 без BOM. Код 0 означает сбор четырёх записей; код 2 — неполный сбор; завершающая ошибка PowerShell — сбой подготовки/исполнения. Код 0 не доказывает наличие обязательных полей, исполнение Sigma или обнаружение в SIEM.

Приватный результат включает stdout/stderr и events.json. Он может раскрывать имена пользователей, хостов, адреса и командные строки. Создавайте результат в приватном каталоге с ограниченными правами. Исключение lab-output из git предотвращает случайный коммит, но не контролирует доступ. Реальные исходные данные не публикуйте. Для прослеживаемости источника храните исходный XML Security приватно: манифест не подписан, предоставляется оператором и не доказывает подлинность.

## Офлайн-оценка на Linux или Windows

Установите toolkit по инструкции репозитория. Для реального сбора используйте его events.json. Исполняемый пример ниже явно синтетический.

```bash
detkit lab-check examples/windows-lab.synthetic.json --observed-at 2026-10-13T10:00:20Z --output lab-assessment.json
```

Ожидается код 2: девять проверок проходят, три проверки доставки в SIEM остаются not_tested. Выходной файл не должен существовать. Коды: 0 — полная оценка, 1 — проваленные проверки, 2 — неполная оценка, 3 — некорректный ввод/вывод. lab-import только валидирует и нормализует; код 0 означает успешный импорт, а не готовность обнаружения.

## Контракт и передача в SIEM

windows-lab-1.0 требует schema_version, synthetic (строго boolean), execution_id, started_at, completed_at, collection_state, commands, events, siem_delivery=not_run и provenance=operator_supplied_unverified. Пример в репозитории задаёт точные ключи команд/событий. Требуются четыре известные команды, уникальные положительные PID и уникальные ID записей. Интервал не более часа; принимаются не более 256 выбранных событий. Неизвестные ключи, повторные JSON-ключи и UTF-8 BOM отклоняются. Классификацию задаёт оператор; она не подтверждена независимо. Старые манифесты без synthetic нужно собрать заново или явно классифицировать после проверки происхождения.

Отображение: NewProcessName → Image; CommandLine → CommandLine; шестнадцатеричный NewProcessId → десятичный process_id; EventRecordID → record_id. Недоступная телеметрия остаётся неизвестной. Отсутствие командной строки ipconfig проваливает проверку полей. Предикаты — офлайн-приближение, а не исполнение Sigma.

Для проверки SIEM настройте реальный источник событий и отображение полей на выбранном стенде, сгенерируйте правило/запрос toolkit для каждой техники и выполните его на положительных и отрицательных контролях. Сохраните приватно время доставки, ID событий SIEM, хеши запросов/правил, фактические совпадения и результат отрицательного контроля. Автоматической загрузки и проверки результатов SIEM здесь нет; импорт сохраняет delivery=not_run. Ручное редактирование JSON не доказывает независимо проверенное обнаружение. Зафиксируйте результат до/после в шаблоне кейса.
