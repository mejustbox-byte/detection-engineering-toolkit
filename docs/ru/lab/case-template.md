# Кейс проверки обнаружения

Для публикации используйте синтетические или проверенные обезличенные данные. Исходные доказательства храните приватно. Пустое поле означает отсутствие проверки, а не успех.

| Доказательство | До изменения | После изменения |
| --- | --- | --- |
| Класс: synthetic / реальные данные оператора | | |
| Сборка Windows, PowerShell, версия SIEM | | |
| Действующая политика аудита и изменение | | |
| ID исполнения и интервал UTC | | |
| Положительные/отрицательные контроли и ID событий | | |
| Время доставки и задержка | | |
| Отображение Image/CommandLine | | |
| SHA256 правила/запроса и фактический запрос | | |
| Положительные совпадения / ожидаемое число | | |
| Отрицательные совпадения / ожидаемый ноль | | |
| Статус исполнения Sigma/SIEM | | |
| Исключения, ложные срабатывания, неизвестное | | |
| Приватное место доказательств и проверяющий | | |
| Результат отката снимка/политик | | |

Укажите причину сбоя, точное изменение и измеренный результат. Разделяйте проверки предиката, конвертацию, доставку и реальное исполнение в SIEM. Без измеренных событий нельзя заявлять задержку или долю обнаружений. Рецензию и обезличивание фиксируйте отдельно: они не доказывают подлинность источника.
