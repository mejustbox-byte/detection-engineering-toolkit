# Архитектура

## Состав

| Модуль | Ответственность |
|---|---|
| `cli.py` | argparse, UTF-8 stdout, dispatch, коды завершения |
| `core.py` | Входы, сценарии, Sigma, конвертация, validation, Atomic, export, integrity, doctor |
| `data/scenarios.json` | Четыре проверяемых рецепта с false positives |
| pySigma и backend | Парсинг Sigma и преобразование поля/условия в целевой запрос |

## Потоки данных

`bundle` сначала готовит все строки в памяти: сценарий → Sigma → два запроса → fixtures/report → optional Atomic plan → manifest. Только после успешной подготовки создаётся новый output каталог. Ошибка подготовки не создаёт каталог. Ошибка файловой записи может оставить частичный каталог; удалите его после анализа или выберите новый путь. Атомарный publish каталога не реализован.

`convert-file` читает внешний Sigma отдельно от каталога. `validate` оценивает только встроенный predicate. `verify-bundle` сравнивает локальные байты с manifest. `doctor` использует реальные backend и packaged data, но не проверяет backend API.

## Границы доверия

Checkout/установленные зависимости — код. Входной YAML/JSON — недоверенные данные. Atomic command сохраняется как текст и не выполняется. SIEM/Windows VM — внешняя система, проверяемая вручную. Manifest — локальная запись целостности без подписи.

Сеть используется установкой и CI, не runtime CLI. Секреты и реальные события не входят в git. Обоснование решения: [ADR](docs/adr/0001-deterministic-offline.md).
