# Модель угроз

## Активы и нарушители

Активы: целостность правил и запросов, рабочая станция инженера, одноразовый стенд, реальные журналы и SIEM credentials, честность результатов проверки. Угрозы: недоверенный Atomic YAML, скомпрометированные зависимости, ошибочный выбор процедуры, ложное чувство покрытия, публикация внутренних событий.

| Угроза | Контроль | Остаточный риск |
|---|---|---|
| Выполнение команды из YAML | Только safe_load; нет shell/subprocess | Оператор может запустить опасный тест вручную |
| Инъекция в пример Invoke-AtomicTest | Строгий technique ID и UUID | Параметры локального модуля и сам модуль требуют review |
| Запуск всех процедур техники | Обязателен конкретный GUID | GUID может принадлежать неподходящей процедуре |
| Подмена YAML после review | SHA256 в Atomic-плане | Нужно сверить фактически установленный файл перед запуском |
| Полное покрытие по одному признаку | Experimental, scope и not_run | Discovery сигналы имеют высокие false positives |
| Утечка логов/секретов | Offline runtime, синтетические fixtures | Пользователь может включить свои данные в cases/output |
| Перезапись результатов | Новый эксклюзивный каталог | Частичная запись при сбое диска |
| Supply chain | Lock, хеши, фиксированный build backend | Lock не заменяет vulnerability audit |
| YAML resource exhaustion | Ограничение файла 8 MiB, обработка recursion | Аномальные alias-графы могут потребовать значительную память |

## Границы

Нет эксплуатации, credential access, persistence, evasion или удалённого runner в этой версии. Сценарии Discovery не требуют этих возможностей. Cleanup — тоже операция изменения стенда; оператор читает его до запуска и использует snapshot rollback.

Приватные события, usernames, hostnames и SIEM endpoints не включаются в публичные демонстрационные материалы. Публиковать можно синтетическую демонстрацию и очищенные доказательства с разрешения владельца. Секреты не передаются инструменту.
